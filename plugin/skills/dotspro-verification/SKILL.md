# DotsPro Verification Skill

## Creating work

When accepting a non-trivial task, state explicitly (in the thread):

- **Acceptance criteria** (checklist)
- **Expected deliverables**
- **Verification steps**

Keep that ledger visible; update it as you go.

## During work

- Attach or cite evidence (paths, URLs, command outputs, screenshots).
- Record blockers honestly; do not invent progress.

## Before claiming done

1. Walk every acceptance criterion. Mark each met/unmet with evidence.
2. If any criterion is unmet, status is **not** `VERIFIED_COMPLETE` — do not tell the user the task is complete.
3. False completion claims violate DotsPro policy.

## Partial work

If some criteria are met, status is `PARTIALLY_COMPLETE`. Say what remains.
